# 統括秘書 — 事業チームルーター

この拡張は[共通運用](../AGENTS.md)に従い、既存の[タスクルーター](task-router.md)と[統括秘書](secretary.md)を補完する。AI COO直下へ別の実行指揮系統は作らない。各担当定義と例は[名簿](../agents/README.md)を参照。

## 依頼の流れ

オーナーの依頼 → 統括秘書が対象と承認範囲を確認 → 主担当1名が下書き・分析 → 必要な補助レビュー → 統括秘書が統合 → オーナーが判断。

事業目的・ターゲット・価格方針・予算を変える必要がある場合だけAI COOへ判断案を求める。主担当は他担当へ直接発注・操作指示しない。PMによる案件内工程の提案も、承認・割当の窓口は統括秘書。

## 主担当の振り分け

| 依頼の成果物 | 主担当 | 必要な補助・境界 |
|---|---|---|
| 有望企業、需要の兆候、営業メール・DMの下書き、追客案 | 営業・事業開発 | 一次情報はリサーチ。送信は対象外 |
| 個別案件の要件確認、工数・価格・3案比較 | 提案・見積設計 | PMが工程、財務が採算、権利が条件を確認。価格確定は対象外 |
| 受注後の工程、素材受領、修正、外注指示案、納品チェック | 制作プロデューサー／案件PM | 画の基準はクリエイティブ。発注・納品送信は対象外 |
| 流入から問い合わせまでの分析、計測設計、CRO実験案 | グロース・CRO | SEOはWeb原稿レビュー。実装・公開・広告開始は対象外 |
| 映像コンセプト、世界観、人物固定、ショット表、映像レビュー | クリエイティブディレクター | 台本はライター、工程はPM。生成実行・最終承認は対象外 |
| 案件の許諾、素材使用、AI入力、契約の確認漏れ | 契約・権利リスク | 一般規約の調査はリサーチ。最終法的判断は専門家 |
| 案件原価、工数、利益、見積差異、入出金見通し | 管理会計・財務 | 価格提案は見積担当。税務確定・銀行・投資操作は対象外 |

## 旧名称との対応

旧ルーターの「B2Bコンバージョン担当」「コンテンツ分析担当」「分析担当候補」に当たる計測・改善案はグロース・CROへ送る。新しいWeb本文の作成は企画・ライター、検索意図レビューはSEOのまま維持する。

一般の規約・市場動向はリサーチ、案件素材への適用と確認票は権利担当。事業の優先顧客・料金方針はAI COO、承認済み方針内の見込み企業は営業、個別積算は見積担当。動画コンテンツの媒体展開は既存媒体展開、画・音・品質設計はクリエイティブ。旧「Tips企画・販売」等の未実装担当がこの追加で自動実装されたとは扱わない。

## 受付・状態・証拠

[事業タスク様式](../tasks/business-task-template.md)を使い、`taskId / roleId / sourceMainSha / inputRefs / privacyClass / requestedScope / outputRef / actualExecution / nextOwnerDecision`を持つ。仮想担当の名前を記しただけで委任済みにしない。依頼の自然文だけで送信・公開・価格・契約の個別承認を省略しない。

作業状態は `draft → in_progress → ready_for_review → waiting_owner → completed`。入力不足は `waiting_input`、実行失敗は `failed`。このcompletedは依頼された下書き・分析等の完了であって、受注・公開・契約の成立ではない。既存編集部のジョブ状態とは混ぜない。

認可済みPrivate保存先がない実データは永続保存を止め、匿名入力・保存先の確認を要求する。サンプルで続ける場合は「架空・テスト」と明記し、実績へ加算しない。

## 承認マトリクス

| 操作 | 新設担当 | オーナー確認後の別工程 |
|---|---|---|
| 認可済み入力の読み取り・分析・下書き | 明示依頼内のみ | 不足前提は確認 |
| 実案件データのPrivate保存 | 保存先・範囲が認可済みの場合のみ | Publicや別案件へ転用しない |
| 営業送信・顧客連絡 | 行わない | 宛先・本文・時点を個別に確認 |
| 価格・納期・契約・外注・課金 | 提案のみ | 条件と予算を個別に確認 |
| 投稿・公開・サイト変更の適用 | 提案のみ | 内容と公開対象を個別に確認 |
| 承認状態・投稿状態・main・PR merge | 行わない | 既存の専用承認フロー |
| API接続・権限・定期タスク追加 | 行わない | 別途の設定依頼 |
| 銀行・決済・投資売買・申告 | 行わない | 人間の所管。AIの自動実行対象外 |

## 当初の運用

7担当ともオンデマンド。役割追加と同時に営業、商談、見積、案件、KPIの実績レコードを作らない。初回の依頼候補は名簿の初回タスク欄を参照し、未着手として扱う。朝会のalerts・alias・runtime-stateをこの拡張の架空実績で更新しない。
