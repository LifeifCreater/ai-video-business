# タスクルーター

## 目的

依頼をAI COO、実装済みの専門担当、レビュー担当、または将来の担当候補へ適切に引き継ぐ。実装済み担当はAI動画リサーチ、コンテンツ企画、コンテンツライター、媒体展開、SEO、編集・校正担当である。

## ルーティング原則

1. 依頼の媒体ではなく、主目的と最終成果物で主担当を決める。
2. 主担当は1つにし、補助担当は必要最小限にする。
3. 基幹コンテンツの新規作成は企画・ライター担当、承認済み企画・原稿の複数媒体展開は媒体展開担当を主担当とする。
4. 事実・顧客情報・権利・価格に不確実性があれば、制作前に統括秘書へ戻す。
5. 各担当の成果物は統括秘書の品質確認とオーナー承認を必須とする。
6. 担当が未実装の場合、統括秘書は要件と構成案まで整理し、未委任として記録する。
7. AI動画リサーチ担当の提出物は調査資料であり、そのまま公開用コンテンツへ転用しない。
8. 事業方針や複数領域にまたがる判断はAI COOへ上げ、AI COOの提案を承認済み判断として扱わない。
9. FRAMEPACTのサービス条件・実績は事業情報正本、外部情報は期限内のverified調査に限定し、未承認・期限切れ情報は担当へ渡さない。

## 複合依頼の扱い

- コラムをXへ展開する: コンテンツライター担当が承認済み基幹原稿を作り、媒体展開担当がX向けに再構成する。SEO担当はXをレビューせず、編集・校正担当が媒体文面をレビューする
- Tips商品の一部をコラム化する: Tips企画担当候補が商品との境界を決め、企画・ライター担当がWeb原稿化し、SEO担当がレビュー
- 制作事例を複数媒体へ展開する: B2Bコンバージョン担当が承認済みの事実と訴求軸を定義し、各媒体担当が編集
- 調査をもとに複数企画を作る: AI動画リサーチ担当が出典付き調査メモを作り、統括秘書が検証後に企画の優先順位と割り振りを決める

## AI動画リサーチ担当への依頼フロー

1. 統括秘書が依頼元タスクID、調査目的、対象範囲、対象期間、活用先、期限を整理する。
2. `research/research-template.md` をもとに調査票を作り、`research/inbox/` に保存する。
3. AI動画リサーチ担当は `agents/researcher.md` に従い、結果を `research/raw/` に提出する。
4. 統括秘書は重要主張の出典、アクセス可否、公開日・確認日、鮮度、事実と推測の分離、FRAMEPACTとの関連性、個人・顧客情報を確認する。
5. 合格した資料だけを `research/verified/` に移す。不合格は修正点を記録して `research/raw/` に戻す。
6. 検証済み資料を使う場合も、公開用コンテンツは別タスク・別ファイルとして作り、品質確認とオーナー承認を行う。

`research/verified/` は調査手続きへの合格を示すだけで、公開許可や内容の永久的な正しさを保証しない。

## AI COOへのエスカレーション

AI COOへ上げる依頼は `business/opportunities/` または該当する事業台帳へ記録する。AI COOは不足情報を推測で断定せず、調査目的と判断事項を統括秘書へ返す。統括秘書がAI動画リサーチ担当へ割り振り、検証済み結果をAI COOへ戻す。

AI COO提案の状態は `提案中 / 追加調査中 / オーナー判断待ち / 承認 / 保留 / 却下 / 検証中 / 完了` のいずれかとする。オーナーが `承認` と記録するまで、統括秘書は実行タスク化しない。

## コンテンツ企画担当へ直接割り振らない依頼

次は企画担当へ直接渡さずAI COOへ上げる。

- 事業方針またはターゲット顧客の変更
- 価格変更、新サービスの正式決定、販売チャネルの変更
- Tipsの事業上の位置付け変更
- 複数事業にまたがる優先順位変更

## コンテンツ企画フロー

`事業目的 → 統括秘書の依頼整理 → 必要なリサーチ → verified調査 → planning/drafts → 統括秘書レビュー → planning/review（修正時） → オーナー企画承認 → planning/approved → ライター引き継ぎ → 本文品質確認 → オーナー公開承認`

`planning/approved/` は企画だけの承認であり、本文や公開の承認ではない。

## コンテンツライター担当へ直接割り振らない依頼

- 事業方針の決定、対象顧客の変更、価格決定、新サービスの正式決定: AI COOへ
- コンテンツテーマの新規決定: コンテンツ企画担当へ
- 調査結果の作成、事実確認: AI動画リサーチ担当へ
- SEOレビュー: ライター原稿作成後にSEO担当へ。修正依頼は統括秘書を経由
- 公開の最終判断: オーナーへ

## 原稿作成フロー

`事業目的 → 企画依頼 → 企画書 → verified調査 → オーナー企画承認 → 統括秘書の執筆依頼 → writing/inbox → SEOレビュー → writing/review → 編集・校正 → オーナー原稿承認 → writing/approved`

`writing/approved/` は原稿承認であり、投稿・公開・販売済みを意味しない。

## SEOレビューのルーティング

- Webコラムとサービスページは、ライターの原稿作成後にSEO担当へ依頼する
- X、動画台本、Tipsは原則対象外。検索流入を主目的とするWeb公開物の場合だけ対象にする
- SEO担当は企画担当・ライター担当と並行して制作せず、後工程でレビューする
- SEO担当の修正提案は `writing/review/` に保存し、統括秘書がライター、企画担当、リサーチ担当へ割り振る
- 企画目的の変更は企画担当またはAI COOへ、外部根拠の不足はAI動画リサーチ担当へ戻す
- SEOレビュー合格を公開承認として扱わない

## 編集・校正レビューのルーティング

- WebコラムとサービスページはSEOレビュー後に編集・校正担当へ割り当てる
- X、Tips、動画台本も、それぞれの媒体別テンプレートに沿った原稿なら編集・校正対象にできる
- 編集・校正担当は企画目的、検索意図、SEO方針、事実関係を変更しない
- 修正提案は `writing/review/EDIT-原稿ID.md` に保存し、統括秘書がライターへ割り振る
- 根拠不足はAI動画リサーチ担当へ戻す
- 企画不整合はコンテンツ企画担当へ、事業目的やCTA方針の不整合はAI COOへ戻す
- 編集修正で検索意図、title、description、見出し、キーワード配置が変わる場合はSEO再レビューへ戻す
- 編集・校正合格を原稿承認または公開承認として扱わない

## 媒体展開のルーティング

- `planning/approved/` の企画または `writing/approved/` の原稿がある場合だけ媒体展開担当へ割り振る
- SEO記事をそのまま転載させず、媒体ごとの目的、読者、単独価値、CTA、重複回避方針を指定する
- 媒体展開担当は元企画・元原稿を変更しない
- 新しい外部事実が必要ならAI動画リサーチ担当、新しい企画判断が必要ならコンテンツ企画担当へ、統括秘書経由で戻す
- X、note、ココナラ、動画の下書きは編集・校正担当のレビュー対象とする
- X、ココナラ、動画はSEOレビュー対象外。noteは検索流入を主目的とする場合だけSEOレビュー対象にできる
- 投稿、販売、公開は媒体ごとにオーナー承認を記録した後、人が行う。自動投稿は別途明示承認された場合だけ検討する
- 成果物は `distribution/` 配下と `distribution/distribution-register.md` で管理する

## 編集長へのルーティング

- 媒体展開案が揃った後、公開準備キューへ登録する前に編集長へ週間選定を依頼する
- 編集長は `問い合わせ / 信頼形成 / 認知獲得` を分類し、投稿上限、テーマ・CTAの連続、単独価値、重複、リスクで採用・保留・不採用を決める
- 編集長は事実・企画・原稿を変更せず、必要修正を統括秘書へ返す
- 採用は公開承認ではない。キューはオーナー確認待ち・未公開で開始する

## 引き継ぎ前チェック

- タスクID、目的、優先度、期限がある
- 対象読者と読後に期待する行動が明確
- 成果物の形式と完了条件が明確
- 使用可能な事実、素材、出典が整理されている
- 禁止事項、機密区分、承認者が明確
- 類似コンテンツと差別化方針が記録されている
- 未確定事項と仮定が分離されている

## 統括秘書へ戻す条件

- 依頼目的が競合して主目的を選べない
- 既存企画と実質的に重複する
- ブランド方針または禁止事項に抵触する可能性がある
- 顧客名、実績、数値、料金、権利について裏付けがない
- 外部公開・投稿・販売・送信操作を求められた
- オーナーの判断なしでは影響範囲が大きい
