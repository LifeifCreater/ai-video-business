# よっしーAIを含む内部PDCA

[共通運用](../AGENTS.md)と[事業ルーター](business-team-router.md)の補足。オンデマンドで起動し、許可された依頼の分析・下書き・修正を進める。常駐サービスや新しい定期タスクは作成しない。

## 1サイクル

1. Plan: 秘書が目的・対象・現状・承認範囲を整理。戦略案が必要な場合はCOOへ依頼し、よっしーAIが判断基準への適合を評価する。
2. Do: 主担当1名が許可範囲の分析・下書き・検証を実施。未承認企画の執筆や公開実装など、既存ゲートを越えない。
3. Check: 必要な専門レビューとよっしーAI評価を秘書が回収。差し戻し条件・証拠・未取得項目を分ける。
4. Act: 同一範囲の修正を主担当へ戻す。最大2巡で収束しなければ保留し、必要な本人判断だけをまとめる。
5. 外部施策の実施後は、確認できる期間・母数・結果に基づき次の仮説を作る。未公開案に売上効果を付けない。

## 責任と証拠

割当・状態管理は秘書、戦略案はCOO、判断基準適合はよっしーAI、専門成果物は主担当、最終承認は本人。同一アシスタントによる役割切替と独立エージェント実行を区別する。実行者・日時・入力版・成果物・確認結果を記録し、役割名だけで委任済みにしない。

既存週次企画・夜間制作では、定義がmainへ反映され実行時に読み込まれた場合だけ内部レビューとして使う。予約済みタスクのプロンプトはこの文書の変更だけで更新されたとみなさない。朝会は従来の読み取り専用集計を維持し、AI適合評価を本人承認・実績へ加算しない。新しい通知やスケジュールは追加しない。

## 保存と終了

Publicには空様式・一般方針・架空テストだけを置く。実案件・個人の判断履歴は認可済みPrivate領域がある場合だけ保存し、なければ会話内で結果を返す。既存runtime-state・job-register・locksへ一般事業タスクを追加しない。

本人への報告は「推奨と理由 / 完成した成果物 / 未解決事項 / 必要な判断」の順。AI推奨でowner approvalを埋めない。定義・main反映・実行時読込・定期タスク反映・実行証拠を別々に扱う。
