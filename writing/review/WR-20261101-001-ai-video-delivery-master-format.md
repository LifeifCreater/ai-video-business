## 本文

# AI動画の納品ファイルを決める前に｜画質・容量・編集用途の確認表

「1080pで納品してください」。この一言だけでは、受け取った動画が社内で再生できるか、後から編集できるか、配信先にそのまま載せられるかまでは決まりません。

納品前にそろえたいのは、**使う目的・ファイル仕様・受け入れ条件**の3つです。この記事では、企業の広報・研修・制作進行担当者が、制作会社と確認するための実務上の整理方法を紹介します。特定の形式や数値を、すべての案件の正解として勧めるものではありません。

## 1. 最初に、納品ファイルの用途を4つに分ける

一つの動画に、軽さ、編集のしやすさ、保管、各媒体への適合をすべて求める前に、必要な用途を分けてみましょう。以下は発注時の整理例です。必ず4種類を発注する必要はなく、同じファイルで兼ねられる用途もあります。

| 用途 | 優先して決めること | 受け取り時の確認例 |
|---|---|---|
| レビュー用 | 内容を確認しやすい共有方法と容量 | 確認対象の版、視聴期限、確認する項目 |
| 再編集用 | 編集先のソフト・バージョンと必要な素材 | 読み込み、映像・音声の扱い、必要な同梱物 |
| 保管用 | どれを正本にし、誰が管理するか | 正本の版番号、保存先、保持期間、復元担当 |
| 公開用 | 実際の配信先・再生環境の要件 | 比率、容量、字幕、音声、指定環境での再生 |

たとえば社内確認は軽量版、展示会では会場の再生環境に合わせた版、将来の修正には別の編集用ファイルが必要、という整理ができます。これは納品構成の例であり、FRAMEPACTの標準納品物を示すものではありません。

## 2. 解像度・ファイル形式・ビットレートを分けて考える

**解像度は映像の縦横の画素数、ビットレートは1秒あたりのデータ量です。** Adobeの公式資料でも、ビットレートと画質・再生負荷の関係や、形式・コーデックによって設定項目が変わることが説明されています。[出典1](https://helpx.adobe.com/media-encoder/desktop/encoding-and-exporting/export-settings-reference.html)

MP4やMOVという拡張子だけで、画質や編集時の使いやすさを判断しないようにしましょう。コンテナは映像・音声をまとめる形式、コーデックはそれらを符号化・圧縮する方式です。発注時は「拡張子」だけでなく、中の映像・音声の仕様と、使うソフトを組にして確認します。[出典1](https://helpx.adobe.com/media-encoder/desktop/encoding-and-exporting/export-settings-reference.html)

同じ解像度でも、圧縮の条件が違えば、画の見え方や容量は変わります。一方で、ビットレートだけを高くしても、元の映像にない細部が必ず増えるわけではありません。「MOVなら常に高品質」「容量が大きければ必ず良い」と決めつけず、対象の映像と環境で比較することが大切です。

Adobeの書き出し手順でも、形式に加えてフレームサイズ・フレームレート・縦横比、音声のチャンネル・サンプルレート・ビットレートを確認します。納品仕様も、こうした項目をまとめて確認する形にすると認識の違いを減らせます。[出典2](https://helpx.adobe.com/premiere/desktop/render-and-export/export-files/export-video-and-audio-files.html)

## 3. 発注前に埋める、納品仕様の確認表

数値が分からない項目は空欄のまま確定せず、**誰が、いつまでに、何を確認するか**を記録します。配信先の指定値と、制作側が提案する設定値も分けておきましょう。

| 項目 | 発注前に確認する内容 |
|---|---|
| 用途と利用先 | 社内確認、会場上映、Web公開、後日の再編集など。具体的な利用先も記載 |
| 形式と互換性 | コンテナ、映像・音声コーデック、再生・編集ソフトとバージョン |
| 映像 | 解像度、縦横比、フレームレート、ビットレートとその決め方 |
| 色 | SDR/HDRなどの扱い、色の確認環境、変換する場合の確認者 |
| 音声・字幕 | 音声の有無、チャンネル、言語、字幕を映像に入れるか別ファイルにするか |
| 容量と受け渡し | 1ファイル・一式の上限、転送方法、ダウンロード期限、受領先の制限 |
| 再編集の範囲 | 完成動画の加工だけか、プロジェクトファイル・素材一式まで必要か |
| 版と正本 | ファイル名、版番号、正本の指定、保存先、保持期間、管理担当 |
| 受け入れと再書き出し | 確認環境、確認期限、問題の報告先、仕様変更時の対応範囲 |

「編集できる動画」という言葉だけで依頼せず、**何を変更したいのか**も伝えます。文字の差し替え、音声の変更、尺の短縮など、想定する作業が違えば、確認する納品物も変わります。追加の素材や形式が必要な場合の費用・範囲は、見積もり時に相談してください。

## 4. 確認版と正本を、ファイル名と一覧で区別する

受け取った順番や「最終」「最終2」という名前だけで正本を判断せず、用途と版が分かる命名ルールを決めておくと引き継ぎやすくなります。たとえば、次のような架空の命名例が考えられます。

```text
sample_review_v03.mp4
sample_master_v03.[合意した拡張子]
sample_web_v03.mp4
```

あわせて納品一覧に「用途・ファイル名・版・容量・正本かどうか・確認者」を記載します。上の拡張子は説明用の例で、推奨形式や納品保証ではありません。

保管先については、ファイルだけでなく仕様表と確認結果も同じ案件単位で残す方法を提案します。公開後の変更管理は別の工程なので、必要に応じて[企業動画の修正・差し替えの確認手順](https://framepact.jp/published-video-replacement-rollback.html)も参照してください。

## 5. 容量を減らす前に、どの用途のファイルかを確認する

社内メールの添付上限に合わせるために、編集用や保管用まで一律に軽くするのではなく、軽量な確認版を別に用意できるか検討しましょう。転送手段を変える方法と、映像を再圧縮する方法も分けて考えます。

比較するときは、同じ場面・同じ画面サイズ・同じ再生環境で確認する方法を勧めます。細かな文字、ロゴ、動きの大きい場面、暗部やグラデーションなど、目的にとって重要な箇所を選んでください。これは実務上の比較方法であり、画質を保証する検査基準ではありません。

公開先ごとの縦横比や構成まで決めたい場合は、[複数媒体への動画展開を見据えた制作設計](https://framepact.jp/multi-platform-video-production.html)が別の確認軸になります。この記事では、納品ファイルの受け渡しと受け入れに範囲を絞ります。

## 6. 「届いた」で終わらせない、受け入れ確認

納品時には、発注時の仕様表と実際のファイルを照合します。たとえば、次の順番で確認すると、内容の確認とファイルの確認を分けられます。

1. **一式がそろっているか。** 納品一覧とファイル数・名前・版を照合し、確認版と正本を区別する。
2. **指定環境で開けるか。** ダウンロードした実ファイルを、合意した端末・ソフトで開く。
3. **冒頭から末尾まで再生できるか。** 尺、映像の欠け、意図しない黒画面、音声の途切れを確認する。
4. **音声・字幕・表示は合っているか。** 無音指定、言語、字幕の表示、固有名詞、ロゴ、最新版の内容を確認する。
5. **再編集の目的を満たすか。** 再編集用を依頼した場合は、対象ソフトへの読み込みと合意した変更作業を確認する。
6. **確認結果を残したか。** 対象ファイル、確認環境、確認者、結果、未解決の問題を記録する。

問題を報告するときは、ファイル名と版、発生箇所の時刻、再生環境、期待した状態を添えます。再書き出しで対応する範囲と、追加の仕様変更になる範囲は、事前に合意しておきましょう。

## 7. 制作相談で共有する、最初のメモ

形式の専門知識がなくても、**どこで使うか、後から何を変えたいか、受け取り側にどんな制約があるか**を整理すると相談を始めやすくなります。以下を打ち合わせのメモとして利用してください。

```text
動画の目的・想定視聴者：
公開・上映する場所：
確認に使う端末・ソフト：
将来の再編集の予定と変更したい箇所：
希望する尺・縦横比：
字幕・音声の必要条件：
容量・転送方法・視聴期限などの制約：
納品希望時期と受け入れ確認の担当者：
未決定で相談したい項目：
```
