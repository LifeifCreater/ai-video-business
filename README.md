# FRAMEPACT

企業向けAI動画制作サービス「FRAMEPACT」の静的サイトです。

## YouTube制作実績の追加

トップページの `worksData` に実績を追加し、`youtubeUrl` に通常のYouTube URL、共有URL、またはShorts URLを貼り付けると、サムネイルとサイト内プレイヤーが自動で表示されます。サムネイルを個別指定したい場合だけ `thumbnail` を追加します。限定公開動画も埋め込みできますが、非公開動画は再生できません。

## コンテンツ統括秘書

FRAMEPACTの認知拡大、企業からの動画制作相談獲得、コラム、X、Tipsの運用を一元管理するための基盤です。最初の専門担当としてAI動画リサーチ担当を実装しています。外部投稿機能は実装していません。すべての公開用成果物は下書きまたはレビュー待ちとして管理し、オーナーの明示的な承認を必須とします。統括秘書とリサーチ担当はX投稿、Tips投稿、記事公開、顧客への送信を行いません。

## 事業運営と組織構造

```text
オーナー（最終意思決定）
  ↓
AI COO（事業方向・優先順位・KPI・意思決定案）
  ↓
コンテンツ統括秘書（分解・割当・進行・品質・承認記録）
  ↓
専門担当AI（並列）
  ├─ AI動画リサーチ担当（事実・情報源）
  ├─ コンテンツ企画担当（テーマ・構成・媒体展開）
  └─ コンテンツライター担当（公開前原稿の下書き）
       ↓
     SEO担当（Web原稿の後工程レビュー）
       ↓
     編集・校正担当（公開前の文章・根拠・ブランド検査）
```

AI COOは市場、顧客、商品、営業、コンテンツを横断して事業提案を作る。統括秘書は提案の完全性を確認し、オーナーが承認したものだけを実行タスクへ分解する。AI COOには契約、公開、投稿、営業送信、販売、価格変更、外部操作の権限がない。

AI動画リサーチ担当とコンテンツ企画担当は上下関係ではなく、どちらも統括秘書から依頼を受ける専門担当です。リサーチ担当は事実と情報源を整備し、企画担当は検証済み情報を媒体別の設計図へ変換します。

コンテンツライター担当も並列の専門担当です。承認済み企画と検証済み調査を自然な文章へ変換しますが、事業方針、企画、事実、価格、CTAの目的を独自に変更せず、公開操作も行いません。

SEO担当はライターと並行して原稿を作る担当ではなく、Webコラム・サービスページの原稿作成後に検索意図、重複、title・description・見出し、内部リンク、CTAをレビューします。修正提案は統括秘書を経由し、本文や企画を無断変更しません。

編集・校正担当はSEOレビュー後の原稿について、誤字、文法、論理、重複、確認マーカー、出典、ブランド、CTAを検査します。本文を直接全面改稿せず、修正提案を統括秘書へ提出します。

### 基本運用

1. `tasks/task-template.md` を複製して `tasks/inbox/` で依頼を整理する
2. 重複確認、タスク分解、優先付け、担当候補の判断を行う
3. 着手時に `tasks/in-progress/` へ移し、成果物を `content/` の該当フォルダへ下書き保存する
4. 品質確認後に `tasks/review/` へ移し、オーナーへ判断点を提示する
5. 明示的な承認と依頼範囲の完了後に `tasks/completed/` へ移す

`承認済み` は公開可否の判断記録であり、統括秘書が外部公開を実行することを意味しません。

### AI動画リサーチ担当の使い方

1. 統括秘書が調査目的、依頼元タスクID、対象期間、対象範囲、活用先、期限を整理する
2. `research/research-template.md` を複製し、調査依頼を `research/inbox/` に保存する
3. AI動画リサーチ担当が一次情報を優先して調査し、情報源を `research/source-register.md` に登録する
4. 調査結果を `research/raw/` に保存し、事実、未確認情報、推測、FRAMEPACTへの示唆を分離する
5. 統括秘書が出典、アクセス可否、日付、鮮度、関連性、個人・顧客情報を検証する
6. 合格した資料だけを `research/verified/` に移し、必要なら別のコンテンツ制作タスクを起票する

リサーチ担当の提出物は企画材料であり、そのままX投稿、コラム、Tips商品、サービスページに使用しません。公開用原稿には別途、品質確認とオーナー承認が必要です。

### 正式情報の正本と参照順序

原稿作成前は次の順で確認します。

1. `business/framepact-service-facts.md` — FRAMEPACTの料金、納期、修正条件、権利、提供範囲、問い合わせ・CTA
2. `business/public-experience-facts.md` — 運営者経歴、制作実績、顧客事例の公開可否と承認表現
3. `research/verified/` — 外部サービス、規約、料金、権利、市場情報などの検証済み調査
4. `planning/approved/` — 承認済み企画の目的、対象読者、構成、CTA
5. `brand/` — ブランドトーン、文章、禁止事項

正本で `[オーナー確認待ち]` または未承認の情報は断定して使用しません。verifiedであっても再確認期限切れ、失効、対象規約・バージョン不明の情報は使用禁止です。既存サイト、README、過去原稿だけを根拠に、料金、納期、修正、権利、実績を補完しません。

サービス情報の更新は `business/service-facts-approval-template.md` でオーナー確認を受け、承認日と次回確認日を正本へ反映します。外部情報はリサーチ担当が再調査し、統括秘書が `verified・有効` と確認します。

各担当が推測してはいけない情報には、料金、最低料金、納期、特急対応、修正回数、追加料金、納品形式、商用利用、著作権、生成物の権利、使用ツール、経歴、顧客・案件実績、成果数値、問い合わせ先が含まれます。

### 事業提案から実行まで

1. オーナーがAI COOまたは統括秘書へ相談する
2. AI COOが事業目的、判断事項、不足情報を整理する
3. 必要な調査を統括秘書へ依頼し、統括秘書がリサーチ担当へ割り振る
4. verified調査をもとにAI COOが事業提案を作る
5. 統括秘書が完全性と記録を確認し、オーナーへ提出する
6. オーナーが承認、保留、却下を判断する
7. 承認された施策だけを統括秘書が実行タスクへ分解する
8. 専門担当が下書きを作り、統括秘書が品質・承認を管理する
9. AI COOがKPIと結果を週次・月次でレビューする

### 事業提案からコンテンツ企画まで

1. AI COOが事業目的、対象顧客、優先順位、KPI、検証期間、避ける方向性を示す
2. 統括秘書が企画依頼へ整理し、必要ならリサーチ担当へ調査を依頼する
3. コンテンツ企画担当が `research/verified/` とブランド方針を使って企画書を作る
4. `planning/drafts/` で統括秘書がブランド、重複、事実、CTAをレビューする
5. 修正は `planning/review/` で管理する
6. オーナーの企画承認後だけ `planning/approved/` へ移す
7. 将来のライターが本文下書きを作り、品質確認とオーナーの公開承認を別途受ける

### コンテンツ企画担当への依頼例

```text
依頼元タスクID: FP-20260803-002
関連施策ID: OPP-20260803-001
事業目的: 企業担当者への認知と制作相談獲得
対象読者: AI動画の外注を検討する企業の広報・マーケティング担当者
読者段階: 解決策探索〜比較検討
主媒体: コラム
使用する調査: research/verified/ の関連調査
期待成果: コラム構成、X・Tips・動画への展開、相談CTAの設計
KPI: コラム流入、サービスページ遷移、問い合わせ件数
避ける方向性: ツールランキング、誇大表現、情報商材的な煽り
成果物: 公開用本文ではなく planning/content-plan-template.md に沿った企画書
```

### 企画のステータスと承認

`受付 → 下書き → レビュー中 → 修正中 → オーナー判断待ち → 企画承認`

保留、却下、archiveも記録します。オーナー承認が必要なのは、企画を `planning/approved/` へ移す時点と、将来作成した本文を公開する時点の2回です。企画承認は投稿、記事公開、Tips販売、動画公開を許可するものではありません。

4本柱は「AI動画の最新情報」「企業動画の作り方」「FRAMEPACTの制作過程や知見」「テンプレートや実務ノウハウ」です。追加分類は継続的な必要性が確認された場合だけAI COOへ提案し、承認なしに変更しません。

### 企画承認から原稿作成まで

1. オーナーが企画を承認し、企画を `planning/approved/` へ移す
2. 統括秘書が媒体、目的、CTA、企画ID、調査IDを含む執筆依頼を作る
3. ライター担当が企画と `research/verified/` を確認する
4. 媒体別テンプレートを使い `writing/inbox/` に保存する
5. Webコラム・サービスページはSEO担当がレビューし、結果を `writing/review/` に保存する
6. SEOレビュー後、編集・校正担当が文章、根拠、確認マーカー、ブランドをレビューする
7. 統括秘書が修正をライターへ割り振り、必要なSEO・編集再レビューへ戻す
8. 統括秘書が目的、事実、ブランド、CTA、機密情報を最終確認する
9. オーナーの原稿承認後だけ `writing/approved/` へ移す
10. 公開は別判断とし、AI自身は投稿・公開・販売しない

動作確認またはオーナーの明示依頼に限り未承認企画を使えるが、原稿に外部公開禁止、事実確認未完了、オーナー承認待ちを明記する。

### 媒体別テンプレート

- コラムは `article-draft-template.md`: 長文、見出し、根拠、SEO・編集申し送り
- Xは `x-draft-template.md`: 一投稿一メッセージ、スレッド、文字数、リンク
- Tipsは `tips-draft-template.md`: 無料との差、実務価値、付属資料、販売承認
- 動画は `video-script-template.md`: 映像、ナレーション、テロップ、尺、素材

### 原稿ステータスと承認

`受付 → 下書き → レビュー中 → 修正中 → オーナー判断待ち → 原稿承認`

保留、却下、archiveも記録します。オーナー承認は少なくとも「企画承認」「原稿承認」「公開・投稿・販売の最終承認」に分けます。`writing/approved/` は原稿承認であり、公開済みを意味しません。

writing配下は次の4状態フォルダで運用します。

- `writing/inbox/`: 執筆依頼とレビュー前原稿
- `writing/review/`: SEO・編集レビュー結果、修正中原稿
- `writing/approved/`: オーナーが原稿承認した未公開原稿
- `writing/archive/`: 終了、却下、置換済み原稿

### SEOレビューの対象

Webコラムとサービスページは原則としてSEOレビュー対象です。X、動画台本、Tipsは原則対象外ですが、検索流入を目的とする索引可能なWebページになる場合だけ対象にします。SEO担当は検索ボリュームや順位を根拠なく断定せず、外部調査が必要なら統括秘書からリサーチ担当へ戻します。

全体フローは次のとおりです。

`事業方針 → 企画 → 調査 → 企画承認 → 執筆 → SEOレビュー → 編集・校正 → オーナー承認 → 公開`

### 編集長と公開準備ダッシュボード

編集長は媒体展開案を `問い合わせ / 信頼形成 / 認知獲得` に分類し、投稿上限、単独価値、重複、リスク、CTA、今週性から採用・保留・不採用を決めます。採用は公開承認ではありません。

- `agents/editor-in-chief.md`: 編集長の選定基準、権限、禁止事項
- `distribution/review/editorial-selection-2026-08-week1.md`: 今週の採用・保留・不採用と理由
- `distribution/publish-ready/publish-queue.json`: オーナー確認待ちの採用候補だけを格納
- `distribution/publish-dashboard.html`: ローカルで確認、コピー、承認・公開状態を管理する静的画面

ダッシュボードは認証情報やAPIを使用せず、入力状態はブラウザのlocalStorageへ保存します。投稿・予約投稿・公開は行いません。

ChatGPTから日次確認する場合は、GitHub上の `distribution/publish-ready/publish-queue.json` を読み、`scheduledAt` を日本時間の日付で絞ったうえで、`approvalStatus: approved` かつ `publishStatus: unpublished` の項目だけを「本日の投稿対象」として提示します。`owner_review` は予定候補として区別し、投稿対象として扱いません。

ダッシュボードのチェック状態はlocalStorageだけに保存され、GitHub上のJSONへ自動反映されません。ChatGPTから最新状態を確認するには、オーナー承認、公開日時、公開URLをJSONへ反映してcommit・pushする必要があります。

### AI編集部モバイル運用

モバイル運用ではChatGPTを唯一の操作画面とし、GitHubは正本と監査履歴として裏側だけで使用します。オーナーはスマートフォンから `記事1確認`、`記事1公開`、`X1`、`note1`、`X1投稿した URL`、`KPI` のような短い指示で操作します。詳細設計は `automation/cloud-editorial/mobile-operations.md`、ChatGPTの実行ルールは `automation/cloud-editorial/prompts/mobile-editorial-console.md` を参照してください。

毎朝9時の最初の表示は「今日やること」だけに絞ります。`記事1`、`X1`、`note1` は朝会がその日だけ有効な固定エイリアスとして原稿ID・投稿IDへ対応付け、書き込み直前にmainの最新状態と再照合します。番号だけから推測して別のコンテンツを操作しません。

| 入力 | ChatGPTの表示・操作 |
|---|---|
| `記事1確認` | title、公開URL、PR状態、Checks、残る注意を表示 |
| `記事1公開` | 承認ゲート確認後、対象PRをReady化・mergeし、Cloudflare結果と公開URLを確認 |
| `X1` | 本文、記事URL、ハッシュタグ、完成形を表示 |
| `note1` | タイトル、本文、CTA、ハッシュタグを表示 |
| `X1投稿した URL` | 投稿IDを確認し、`published`、JST投稿日時、投稿URLを状態専用PRで記録 |
| `KPI` | 表示、プロフィール、クリック、問い合わせ、公開記事を取得状況付きで表示 |

記事公開以外ではCloudflareを操作しません。X・noteへの投稿はオーナーが手動で行います。ChatGPTはmainへ直接pushせず、状態更新も1操作1ブランチのPRで監査可能にします。記事公開はオーナーの `記事N公開` を明示承認とし、対象PR、必須Checks、競合、HTML、canonical、sitemap、CTAを確認してから実行します。自動マージや複数記事の一括公開は行いません。

KPIは取得できた値だけを表示します。X・noteのプロフィール表示やクリック、アクセス解析、問い合わせ件数の取得元が未接続の場合は、0と推測せず `未取得` と表示します。媒体や解析サービスの認証情報はGitへ保存しません。

### 次に追加すべき専門担当AI候補

推奨順は次のとおりです。

1. **コンテンツ分析担当** — チャネル横断のKPIを集計し、施策・企画・原稿の継続、改善、停止判断へつなげる
2. **公開運用担当** — 媒体展開担当が作った承認済み成果物について、手動公開チェックリスト、URL、日時、結果を管理する。自動投稿権限は持たせない
3. **B2Bコンバージョン担当** — コラムや事例から動画制作相談へつなぐ訴求、CTA、導線を改善する

どの担当を追加しても、成果物は統括秘書の品質確認とオーナー承認を経る設計にします。
